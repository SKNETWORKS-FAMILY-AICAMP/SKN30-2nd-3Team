# 1. 프로젝트 개요
### 전처리 목적
- 호텔 예약 데이터의 노이즈를 제거하고, 도메인 지식 기반의 파생 변수를 생성하여 '예약 취소 예측 모델'의 성능 및 해석력 극대화

### 데이터 구조 설명
- 호텔 유형(City/Resort), 고객 인원 구성, 예약 시점, 객실 종류, 에이전트 정보 등 예약 행태와 관련된 수치형 및 범주형 변수가 혼합된 구조

### 데이터 출처
- 포르투갈 지역 호텔의 예약/취소 이력을 담은 원시 데이터

### 변수 설명
- 예약 리드 타임, 숙박 일수, 고객 정보(인원, 국적), 예약 경로, 객실 유형, 과거 취소 이력, 최종 요금(ADR) 및 취소 여부(is_canceled) 등으로 구성

# 3. 결측치 및 이상치 처리

> **[기본 전제]**
> 
> - **데이터 무결성**: 데이터 수집 시 누락된 값 없이 수집되었음이 명시됨
> - **해당 없음 판단**: 간혹 누락된 값이 존재할 경우, 이는 데이터 오류가 아닌 '**해당사항 없음**'으로 간주하여 처리함

### 변수별 처리 방법
- **`children`**: 동반 미성년자가 없는 것으로 판단하여 `0`으로 대체
- **`agent` / `company`**: 여행사나 대리 회사를 거치지 않은 개인 예약으로 간주하여 신규 코드 `0` 부여
- **`country`**: 본국(포르투갈)으로 예상되나 데이터 불확실성 제거를 위해 결측치 행 **삭제(Drop)**

---

# 4. 데이터 변환
### 범주형 인코딩 (Label / One-hot)
- 이진화(Binary Encoding)
    - `hotel`: unique 값이 2개 존재, 'Resort Hotel' $\rightarrow$ 1, 'City Hotel' $\rightarrow$ 0
    - `agent`, `company`: ID 값 대신 대행 여부만 식별하도록 1, 0 반환
- 재범주화(Regrouping)
    - **`country`**: 백 수식 개의 국가 코드를 단순화하기 위해 자국인 포르투갈(`PRT`), 포르투갈 외 유럽(`EUR`), 그 외 대륙(`OTH`) 3개 카테고리로 
### 날짜 데이터 처리
- **`arrival_date_year`, `arrival_date_week_number`, `arrival_date_day_of_month`**: 차원 축소를 위해 제거
- **`arrival_date_month`**: 계절성을 반영하는 인자로 판단하여 유지

---

# 5. Feature Engineering
### 파생 변수 생성
- `guest_type`: `adults`, `children`, `babies` 조합
    - `Family`: 성인 $\ge$ 1명 + 아동 또는 유아 $\ge$ 1명
    - `Single`: 1명으로만 구성
    - `Group`: 그 외 조합 (예: 성인만 2명 이상 등)
    - `Undefined`: 인원 정보가 모두 0인 경우
- `diff_reserved_room_type`: `reserved_room_type`과 `assigned_room_type` 비교
    - `1`: 예약한 방과 실제 배정받은 방이 다른 경우 (업/다운그레이드 변동 발생)
    - `0`: 예약한 방과 배정받은 방이 일치하는 경우
### 제거된 변수
- **필요하지 않은 변수**: `arrival_date_year`, `arrival_date_week_number`, `arrival_date_day_of_month`
- **파생 변수 변환 후 원본 삭제**: `hotel`, `reserved_room_type`, `assigned_room_type`, `agent`, `company`
- **데이터 누수(Data Leakage) 방지**: `reservation_status`, `reservation_status_date`
